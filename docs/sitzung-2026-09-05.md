# Sitzungsnotiz vom 05.09.2026

Autark geschrieben: Diese Datei soll ohne den zugehörigen Chatverlauf
verständlich sein, weil der Chatverlauf genau das ist, was verloren

## 1. Die Regel, die heute entstanden ist

**Eine Zusage, etwas sei gespeichert, zählt nicht. Nur die Datei zählt.**

Anlass: Ein langes Gespräch über den Budget-Rechner sollte nach Obsidian
gesichert werden. Dafür gab es gar keinen Weg, denn ein Vault liegt auf
dem eigenen Rechner und ein Connector dorthin war nie eingerichtet.
Aufgefallen ist es erst, als der Inhalt gebraucht wurde.

Drei praktische Folgen:

- Was festgehalten werden soll, wird als Datei angelegt, mit Pfad
  zurückgemeldet. "Ich habe es notiert" ist keine Ablage.
- Was eine Sitzung überleben soll, wird committet und gepusht.
- Fehlt das Werkzeug für den Ablageort, wird das gesagt, **bevor**
  gearbeitet wird.

Steht seit heute in `CLAUDE.md` im Repo, Abschnitt "Gespeichert ist es
erst, wenn die Datei da ist", Commit `52d523a`.

## 2. Frankenstein-Build, Kurzfassung

Ausführlich in `docs/frankenstein-stand.md`, Commit `282a253`. Das
Wichtigste, damit diese Notiz allein trägt:

- **Fest: gebrauchte RTX 3050 8 GB, rund 150 Euro.** Braucht kein
  Resizable BAR, läuft also in jedem Unterbau, und hat RT-Einheiten.
- **Gesucht: Komplettrechner bis 175 Euro**, sechs Kerne, 16 GB, SSD,
  Ziel i5-10400F. Dazu Netzteil 550 W mit PCIe-Stecker für 53 Euro.
  Summe rund 359 Euro.
- **Drei Sperren**, an denen billige Rechner scheitern: SSE4.2 (fehlt
  bei Phenom II und Athlon II), AVX2 (fehlt bei AMD FX und Intel vor
  der 4. Generation), RT-Einheiten (fehlen bei allen GTX und RX 500).
- **Zwei Zahlen sind ungeprüft:** die 60 fps Medium in DOOM The Dark
  Ages auf einer 3050 (optimistisch, Karte liegt nah an der
  Mindestanforderung) und "ReBAR ab der 10. Generation" (stimmt für die
  CPU, hängt beim Fertigrechner am BIOS des Boards). Für diesen Build
  ist Letzteres egal, weil die 3050 ohne ReBAR auskommt.

## 3. Was diese Cloud-Sitzung nicht kann

Nachgeprüft, nicht vermutet:

- **Kein Obsidian.** Kein Connector eingerichtet, Vault liegt lokal.
  Der Container sieht nur das geklonte Repo.
- **Kein USB-Stick.** Fremder Rechner, fremdes Dateisystem.
- **Keine YouTube-Transkripte.** YouTube ist am Proxy gesperrt
  (HTTP 403), `yt-dlp` ist nicht installiert. Gemini kann das, hier
  geht es nicht.
- **Suche geht in die Breite, aber selten von selbst in die Tiefe.**
  Wenn Tiefe gebraucht wird, muss sie ausdrücklich verlangt werden.

Was hier dafür wirklich geht: Quelltext lesen und ändern, bauen,
testen, Behauptungen gegen den Code prüfen, Dateien anlegen und in Git
sichern.

## 4. Arbeitsteilung, die sich daraus ergibt

| Aufgabe | Wohin |
|---|---|
| Videos, Transkripte, breite Recherche | Gemini, Ergebnis als Text herüberkopieren |
| Aktuelle Preise und Verfügbarkeit | Geizhals und Kleinanzeigen, kein Sprachmodell |
| Code, Tests, Dateien, Git | Claude Code |
| Persönliche Ablage | Obsidian-Vault, lokal |

## 5. Orchestrator-Idee: nicht bauen

Vorschlag war, Claude und Gemini per Python-Skript oder n8n zu
verketten. Bewertung: Aufwand lohnt nicht.

- Die Arbeitsteilung "einer denkt, einer holt Live-Daten" gibt es so
  nicht mehr, beide Seiten können suchen.
- Kein Sprachmodell hat verlässliche Hardwarepreise. Bei einem Budget,
  in dem 20 Euro über die Teilewahl entscheiden, ist das der
  entscheidende Punkt.
- API-Keys laufen getrennt vom Abo, also eine zweite Rechnung.
- Copy-Paste zwischen zwei Tabs erledigt dieselbe Aufgabe heute.

Wenn Automatisierung, dann der einfache Weg: Claude Code **lokal** im
Vault-Ordner starten. Dann landet das Ergebnis direkt als Datei in
Obsidian, ohne Server, ohne Keys, ohne Bastelabend.

## 6. Offene Punkte

- Konkreter Fertigrechner unter 175 Euro finden, der die drei Sperren
  nimmt.
- Die beiden ungeprüften Zahlen gegenprüfen.
- Entscheiden, ob persönliche Projektnotizen im **öffentlichen** Repo
  bleiben sollen. `benchmeister-pc-check` ist öffentlich, alles hier
  ist für jeden lesbar. Ein eigenes privates Repo wäre der saubere Ort.

## 7. Wie das hierher kommt, in den Vault und auf den Stick

Die Dateien liegen im Repo auf dem Branch
`claude/benchmeister-frankenstein-cpx7fh`:

- `docs/sitzung-2026-09-05.md` (diese Datei)
- `docs/frankenstein-stand.md`
- `CLAUDE.md` (enthält die neue Regel)

**Von Hand:** Auf GitHub die Datei öffnen, "Raw" anklicken, speichern,
in den Vault-Ordner `01 Projekte/BenchMeister/Konzepte/` legen und
danach auf den Stick kopieren.

**Mit PowerShell**, wenn das Repo lokal schon liegt. Pfade vorher
anpassen, `E:\` durch den Laufwerksbuchstaben des Sticks ersetzen:

```powershell
$repo  = "C:\Pfad\zu\benchmeister-pc-check"
$vault = "D:\Obsidian Zweites Gehirn\Zweites Gehirn\01 Projekte\BenchMeister\Konzepte"
$stick = "E:\BenchMeister"

git -C $repo fetch origin claude/benchmeister-frankenstein-cpx7fh
git -C $repo checkout claude/benchmeister-frankenstein-cpx7fh
git -C $repo pull origin claude/benchmeister-frankenstein-cpx7fh

New-Item -ItemType Directory -Force -Path $vault, $stick | Out-Null
Copy-Item "$repo\docs\*.md" $vault -Force
Copy-Item "$repo\docs\*.md" $stick -Force
Copy-Item "$repo\CLAUDE.md" $stick -Force
Get-ChildItem $vault, $stick -Filter *.md | Select-Object FullName, Length, LastWriteTime
```

Die letzte Zeile ist Absicht: Sie zeigt, was tatsächlich angekommen
ist. Nach der Regel aus Abschnitt 1 zählt nicht, dass das Skript ohne
Fehler durchlief, sondern dass die Datei da ist.
